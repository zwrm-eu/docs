## Global flags

These flags are available on every command:

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--config` | string | `~/.zwrm/config.toml` | CLI configuration file path |
| `--api-url` | string | `https://zwrm.io` | Control plane API URL |
| `--org` | string | from config | Organization slug or ID (overrides env/config) |
| `--verbose`, `-v` | bool | `false` | Enable verbose output |

## `zwrm init`

Initialize a new `zwrm.toml` configuration file.

```bash
zwrm init [--name <name>] [--dockerfile <path>] [--no-prompt] [--no-workflow]
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--name` | string | current directory name | Application name |
| `--dockerfile` | string | `Dockerfile` | Dockerfile path |
| `--no-prompt` | bool | `false` | Use defaults without prompting |
| `--no-workflow` | bool | `false` | Don't create a GitHub Actions deploy workflow |

Build and deploy the application. [Guide →](/apps/deploy)

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--app` | string | from `zwrm.toml` | Application name |
| `--context` | string | `.` | Build context directory |

## `zwrm ssh`

SSH into a running VM, or run a single command on it. [Guide →](/apps/ssh)

```bash
zwrm ssh [machine-id] [flags] [-- command [args...]]
```

Everything after `--` runs on the VM instead of opening an interactive shell; the CLI exits with the remote command's exit code.

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--app` | string | from `zwrm.toml` | Application name |
| `--app-id` | string | — | Application UUID |
| `--machine` | string | — | Machine ID (alternative to positional) |
| `--command`, `-C` | string | — | Remote command (alternative to `-- command`) |
| `--direct` | bool | `false` | Direct connection (host access only) |
| `--tty`, `-t` / `--no-tty`, `-T` | bool | auto | Force / disable PTY allocation |
| `--user` | string | — | SSH user override |

`--machine` also works for app-less machines (Postgres, sandboxes); those connect directly rather than through the proxy, whose usernames are `{app}.{machine}`.

```bash
zwrm ssh -- uptime
zwrm ssh --app myapp -- bash -lc 'cd /app && python3 task.py'
echo 'print(1)' | zwrm ssh -- python3 -
```

## `zwrm sftp`

Transfer files to/from a running VM through the SSH proxy. Run without a subcommand for an interactive SFTP shell, or use one-shot subcommands:

```bash
zwrm sftp get <remote> <local> [-r]
zwrm sftp put <local> <remote> [-r]
zwrm sftp ls <remote-dir>
```

`get` and `put` accept `--recursive` (`-r`) to copy directories. All forms accept `--app`, `--app-id`, `--machine`, and `--user`. Modern `scp` (OpenSSH ≥ 9.0) also works against the proxy directly.

## `zwrm org`

Manage organizations and org-wide resources.

```bash
zwrm org create <name>
zwrm org list
```

### `zwrm org secrets`

Organization-wide secrets, inherited by every app and agent. [Guide →](/secrets)

```bash
zwrm org secrets set <NAME>=<VALUE>
printf '%s' "$VALUE" | zwrm org secrets set <NAME> --stdin   # preferred: keeps the value out of argv/history
zwrm org secrets list
zwrm org secrets unset <NAME>
zwrm org secrets add --from-file <path>
```

### `zwrm org llm-provider`

External OpenAI-compatible endpoints whose models zwrm-runtime and OpenCode agents can use as `ext/<provider>/<model-id>`. Runs on your credential and is billed by your vendor, not against credits. [Guide →](/agents/external-providers)

```bash
zwrm org llm-provider add <name> --base-url <url> [--api-key -] [--model <id>]...
zwrm org llm-provider add azure --base-url <url> --header "api-key: $KEY"   # non-bearer auth
zwrm org llm-provider list
zwrm org llm-provider show <name>
zwrm org llm-provider discover [<name>] [--base-url <url>]   # what does the endpoint serve?
zwrm org llm-provider sync <name>                            # refresh the model list
zwrm org llm-provider update <name> [--base-url <url>] [--api-key -] [--clear-api-key]
zwrm org llm-provider enable <name> | disable <name>
zwrm org llm-provider remove <name>
```

`--api-key -` reads the key from stdin, keeping it out of argv and shell history. Changing `--base-url` clears the stored credential unless `--api-key` rides the same command.

## `zwrm sandbox`

Manage sandboxes. [Guide →](/sandbox)

```bash
zwrm sandbox create --template <name> [--size <preset>] [--timeout <dur>] [--persistent] [--idle-timeout <dur>] [--env KEY=VALUE ...] [--egress-mode allow_all|deny_all] [--egress-allow-cidr <cidr>] [--egress-deny-cidr <cidr>] [--egress-allow-port <port>] [--disk-size-mb <n>] [--bandwidth-mbps <n>] [--ops-per-sec <n>] [--burst-mbps <n>] [--burst-ops <n>]
zwrm sandbox run --template <name> [--size <preset>] [--timeout <dur>] [--exec-timeout <dur>] [--wait-timeout <dur>] [--workdir <dir>] [--env KEY=VALUE ...] [--egress-mode allow_all|deny_all] [--egress-allow-cidr <cidr>] [--egress-deny-cidr <cidr>] [--egress-allow-port <port>] -- <command>   # create, run, destroy
zwrm sandbox exec <id> -- <command> [--timeout 30s] [--workdir <dir>]
zwrm sandbox list [--status running|creating|suspended|destroyed]
zwrm sandbox status <id>
zwrm sandbox upload <id> <local> <remote>
zwrm sandbox download <id> <remote> <local>
zwrm sandbox keepalive <id> [--timeout <dur>]
zwrm sandbox wake <id>
zwrm sandbox destroy <id> [-f]
```

`--template` (`-t`) is required; `--size` (`-s`) defaults to `shared-cpu-1x`. On `run`, `--exec-timeout` defaults to `30s` and `--wait-timeout` (max wait for sandbox readiness) to `2m`. The disk and drive rate-limit overrides (`--disk-size-mb`, `--bandwidth-mbps`, `--ops-per-sec`, `--burst-mbps`, `--burst-ops`) are available on `create` only; unset values inherit the template defaults.

See the [Sandboxes guides](/sandbox) for egress control, persistence, and template details.

## `zwrm templates`

Manage agent and sandbox VM templates. [Guide →](/agents/templates)

`templates create` uploads the complete Docker build context — the current directory by default, or `--context <dir>` — filtered by `.dockerignore`, up to 1 GiB compressed. `COPY` and `ADD` work with local files; `--dockerfile` must point to a file inside the context.

```bash
zwrm templates list
zwrm templates create <name> --dockerfile <path> [--context <dir>] [--description <text>] [--env KEY=VALUE ...] [--egress-mode allow_all|deny_all] [--egress-allow-cidr <cidr>] [--egress-deny-cidr <cidr>] [--egress-allow-port <port>] [--disk-size-mb <n>] [--bandwidth-mbps <n>] [--ops-per-sec <n>] [--burst-mbps <n>] [--burst-ops <n>]
zwrm templates rebuild <name>
zwrm templates update-quota <name-or-id> [--disk-size-mb <n>] [--bandwidth-mbps <n>] [--ops-per-sec <n>] [--burst-mbps <n>] [--burst-ops <n>] [--clear-rate-limit]
zwrm templates delete <name> [-f]
```

## `zwrm agent`

Manage agents. [Guide →](/agents/overview)

### `zwrm agent create`

Create a named agent definition without booting its workspace VM. The runtime is stored on the agent and reused by connect, runs, and chat.

```bash
zwrm agent create <name> --runtime <zwrm|claude|codex|opencode> [--size <preset>] [--template <t>]
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--runtime` | string | — (required) | Agent runtime: `zwrm`, `claude`, `codex`, or `opencode` (beta, enabled per organization; accepted but not yet listed in `--help`) |
| `--size` | string | `performance-2x` | VM size preset |
| `--template` | string | — | Stored template name/ID or public GitHub repository |

### `zwrm agent connect`

Resolve an agent by exact ID or unambiguous name, boot or reuse its workspace VM, and open its configured agent process. If the name doesn't exist yet, an interactive terminal offers to create it first (non-interactive use never creates implicitly). On exit, the VM is destroyed and its workspace volume is preserved.

```bash
zwrm agent connect <agent-ref>
```

### `zwrm agent ssh`

Same resolution and lifecycle as `connect`, but opens a raw interactive shell in the workspace VM instead of the configured agent process.

```bash
zwrm agent ssh <agent-ref>
```

### `zwrm agent run`

Start an autonomous run. [Guide →](/agents/runs)

```bash
zwrm agent run --agent <name> --prompt <text> [--session <key>] [--model <m>] [--effort <e>] [--size <preset>] [--timeout <dur>]
```

### `zwrm agent run status` / `list` / `cancel` / `continue`

### `zwrm agent update`

Update agent configuration (only passed flags change).

```bash
zwrm agent update <instance> [--size <preset>] [--model <m>] [--effort <e>] [--instructions <text>] [--workspace-ttl <dur>] [--daily-budget <usd>] [--max-runs-per-day <n>] [--allowed-scopes <list>] [--disable-boot-token[=false]]
```

`--model` is harness-specific (`opus`/`sonnet`/`fable` for claude, catalog aliases for codex, the zwrm runtime and OpenCode — see [Models](/agents/models)). `--allowed-scopes` takes a comma-separated `resource:action` list; an empty value resets to the platform default. `--disable-boot-token` mints no in-VM `zwrm` credential at the next boot (`--disable-boot-token=false` restores it) — distinct from an empty `--allowed-scopes`, which means the default set. ## `zwrm mcp`

MCP gateway and local MCP server. [Guide →](/context/mcp-gateway)

`zwrm mcp` with no subcommand runs a stdio MCP server exposing your agent runs (`get_agent_run`, `list_agent_runs`, `cancel_agent_run`).

### `zwrm mcp upstream`

```bash
zwrm mcp upstream add <name> <url> [--bearer-token <t>] [--header "Name: value"] [--oauth] [--oauth-client-id <id>] [--oauth-client-secret <s>] [--oauth-token-url <url>] [--oauth-scope <scopes>] [--oauth-issuer <url>] [--transport streamable-http|sse] [--allow-private]
zwrm mcp upstream list
zwrm mcp upstream tools <name>
zwrm mcp upstream sync <name>
zwrm mcp upstream grants <name>
zwrm mcp upstream rm <name> [--force]
```

The auth flags are mutually exclusive. [Guide →](/context/credentials)

### `zwrm mcp connect` / `disconnect`

Connect an account to a per-user OAuth upstream. [Guide →](/context/credentials#connecting-an-account)

```bash
zwrm mcp connect <upstream> [--agent <id|instance>]
zwrm mcp disconnect <upstream> [--agent <id|instance>]
```

`--agent` authorizes that agent instead of yourself — the account you consent with becomes the agent's identity on the upstream.

### `zwrm mcp server`

```bash
zwrm mcp server create <name> --upstream "<name>[:tool1,tool2]" [--upstream ...] [--description <text>]
zwrm mcp server list
zwrm mcp server get <name>
zwrm mcp server add-upstream <server> --upstream "<name>[:tool1,tool2]" [--upstream ...] [--replace]
zwrm mcp server remove-upstream <server> <upstream>...
zwrm mcp server rm <name>
```

`add-upstream` uses the same selection syntax as `create`; adding an upstream already in the composition is an error unless `--replace` is set, which overwrites that upstream's tool selection. `remove-upstream` refuses to remove the last upstream — delete the server with `rm` instead.

On a per-user OAuth upstream, every caller always acts as their own connected account — there is no per-attachment identity setting. [Guide →](/context/credentials)

### `zwrm mcp install`

```bash
zwrm mcp install <server> [--client claude-code|claude-api|cursor|vscode|windsurf|goose|openai|openapi|custom-gpt] [--all]
```

Cron → agent runs. [Guide →](/automations/schedules)

```bash
zwrm schedules list [--agent <name>] [--metadata k=v]
zwrm schedules create <name> --agent <a> --cron "<expr>" --prompt <text> [--session-key <key>] [--metadata k=v] [--paused]
zwrm schedules firings <schedule-id> [--limit 50]
zwrm schedules pause|resume <schedule-id>
zwrm schedules delete <schedule-id>
```

## ID prefix matching

Many commands accept machine, route, or database IDs. You don't need to type the full UUID — just enough characters to uniquely identify the resource:

```bash
zwrm ssh abc1          # matches machine with ID starting with "abc1"
zwrm destroy --machine ab12
zwrm routes delete 7f3
```

If the prefix matches multiple resources, the command fails with an error listing the ambiguous matches.
