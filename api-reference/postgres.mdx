## Databases

Reads return a database's settings with the password redacted. Two responses carry the password: creating a database (`POST /v1/postgres`, once, to its creator) and `GET /v1/postgres/{postgres_id}/connection`.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/postgres` | Create a database |
| `GET` | `/v1/postgres` | List databases |
| `GET` | `/v1/postgres/presets` | List size presets |
| `GET` | `/v1/postgres/by-name/{name}` | Get by name |
| `GET` | `/v1/postgres/{postgres_id}` | Get a database |
| `DELETE` | `/v1/postgres/{postgres_id}` | Destroy a database |
| `POST` | `/v1/postgres/{postgres_id}/stop` | Stop |
| `POST` | `/v1/postgres/{postgres_id}/start` | Start |
| `GET` | `/v1/postgres/{postgres_id}/connection` | Connection string with the superuser password. Routes through the pooler when one is enabled; `?direct=true` returns the raw `:5432` connection. `400` when the database isn't running. Agent and scoped credentials need `postgres:connect`, which agents don't have by default. Every call is audited as `database.credentials_released` |
| `POST` | `/v1/postgres/{postgres_id}/scale` | Scale replicas |
| `POST` | `/v1/postgres/{postgres_id}/studio-session` | Open a Database Studio browser session (requires an interactive dashboard session) |

## Backups & restore

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/postgres/{postgres_id}/backups` | List backups |
| `POST` | `/v1/postgres/{postgres_id}/backups` | Take a backup |
| `GET` | `/v1/postgres/backups/{backup_id}` | Get a backup |
| `DELETE` | `/v1/postgres/backups/{backup_id}` | Delete a backup |
| `POST` | `/v1/postgres/{postgres_id}/wal-archiving` | Enable WAL archiving (point-in-time recovery) |
| `DELETE` | `/v1/postgres/{postgres_id}/wal-archiving` | Disable WAL archiving |
| `POST` | `/v1/postgres/{postgres_id}/restore` | Restore into a new database (backup or PITR target) |
| `GET` | `/v1/postgres/restores/{restore_id}` | Restore progress |

## App links

Linking records the app–database link and opens firewall rules so the app's VMs can reach the database over the private network. No secret is injected into the app — you manage the connection string yourself. On failover, the control plane repoints only the host of a linked app's `DATABASE_URL`, and only when that URL targets this database; user, password, database, query, and port stay as they were, and any other value is left alone. The app must have private networking enabled (`[network] private = true` in `zwrm.toml`), or the link is refused with `400`. See [Linking](/postgres/linking).

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/apps/{app_id}/databases` | Link a database to an app |
| `GET` | `/v1/apps/{app_id}/databases` | List an app's linked databases |
| `DELETE` | `/v1/apps/{app_id}/databases/{postgres_id}` | Unlink |
| `GET` | `/v1/postgres/{postgres_id}/links` | List apps linked to a database |
