## Auth

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/auth/whoami` | The authenticated user and org memberships |
| `POST` | `/v1/auth/tokens` | Create an API token (see below) |
| `GET` | `/v1/auth/tokens` | List tokens |
| `DELETE` | `/v1/auth/tokens/{token_id}` | Revoke a token |
| `GET` | `/v1/auth/sessions` | List CLI sessions |
| `DELETE` | `/v1/auth/sessions` | Revoke all CLI sessions |
| `DELETE` | `/v1/auth/sessions/{session_id}` | Revoke one CLI session |
| `POST` | `/v1/auth/token-exchange` | A trusted app exchanges a member's identity provider token for a zwrm token of theirs (public; the app authenticates itself). See [Trusted apps](/sso-trusted-apps#exchange-it) |

### Scoped tokens

`POST /v1/auth/tokens` mints an unrestricted user token by default. Pass `scopes` to mint a [capability-scoped](/agents/capabilities) token instead, bound to one organization:

```json
{ "name": "ci", "scopes": ["apps:read", "deploy"], "org": "acme", "expires_in": 31536000 }
```

An unknown scope returns `400`; an org you aren't a member of returns `403`. The key is shown once. Requests made with a scoped token outside its capabilities return `403 token is not authorized for this endpoint`.

### Trusted apps

Apps an SSO connection lets exchange its members' tokens. See [Trusted apps](/sso-trusted-apps). Org owners and admins only (others get `404`); `{provider_id}` is the connection's id, the `sso-…` its redirect URI ends with.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/org/sso/{provider_id}/apps` | List the connection's trusted apps |
| `POST` | `/v1/org/sso/{provider_id}/apps` | Trust an app: `{"name", "idp_client_id", "return_origins"}`. The answer carries its `id` (the zwrm App ID) and `client_secret`, shown once. `400` for the connection's own client ID or an origin that isn't https with no path; `409` while the connection's domain isn't proven, for a second app with the same client ID, or past 10 apps |
| `PATCH` | `/v1/org/sso/{provider_id}/apps/{app_id}` | Replace its `return_origins` (https origins; `[]` clears them) |
| `POST` | `/v1/org/sso/{provider_id}/apps/{app_id}/rotate` | New secret; the old one stops working at once, tokens already issued run out on their own |
| `DELETE` | `/v1/org/sso/{provider_id}/apps/{app_id}` | Revoke it: its tokens end and schedules it wrote pause |

### Members who leave

When a member leaves the organization, or is removed from it, zwrm acts within minutes:

- **What they shared keeps working**, and passes to the organization's owner: shared agents, chats, skills, memories, connectors, routines and triggers. An agent can't pass to someone who already has an agent of the same handle; it then goes to the next owner, then admin.
- **What was theirs stops.** Their private routines and triggers pause, the VMs of their private chats and agents stop, and their own sign-ins to the organization's connectors and their phones' notifications are deleted. Nothing runs as them from then on.
- **Their private items wait 30 days**: private agents, chats, skills, memories, connectors, routines, triggers, keys and model providers. An admin can hand them to another member or delete them sooner. After 30 days they are deleted.
- **Their private apps and databases keep running**, and pass to the organization's owner, still private. They are never deleted by themselves: an admin hands them to another member or deletes them. See [Private and shared apps](/apps/sharing#members-who-leave).

If they rejoin before that, everything that was theirs is theirs again, apart from what was handed over or deleted.

Handing over moves everything at once, private as it was. Their own keys and model providers are never someone else's: they stay until they're deleted. Routines and triggers stay paused, and their new owner reviews them before they run again. An agent, skill or memory the new owner already has one of the same name of stays behind; delete it, or hand it to someone else.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/org/departures` | Members who left, latest first: when, who took over what they shared, when the rest is deleted, and what they still own |
| `POST` | `/v1/org/departures/{user_id}/reassign` | Hand everything they still own to a member (`{"to": "<user id>"}`) |
| `DELETE` | `/v1/org/departures/{user_id}/items` | Delete now what they still own privately |

Org admins and owners only, with their own login or token: an agent's credential gets `403`.

## Credits

Prepaid credit balance and the zwrm-runtime metering ledger, in EUR. See [Credits & billing](/billing/credits). Reads are org-scoped and outside the agent-token scope.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/credits` | Balance, currency (`eur`), metering flag, low-balance flag |
| `GET` | `/v1/credits/ledger` | Ledger history, newest-first (`?before_id=`, `?limit=` 1–200) |
| `GET` | `/v1/credits/usage` | Per-agent EUR consumption (today + 7 days) |
| `GET` | `/v1/credits/pricing` | Credit-metered model prices in EUR |
| `GET` | `/v1/org/gateway-usage` | Per-model [gateway](/agents/openai-api) consumption over the last N days (`?days=`) |

Subscriptions and credit-pack purchases run through Stripe in a separate auth service (`/billing/*`), driven from the dashboard — not part of the `/v1` surface.

## Audit logs

The audit log is for an organization's owners and admins. Its entries include the start of each chat message, private chats included, so other members get `403`. Someone who is an admin in one organization and a member in another sees only the first organization's entries.

When an admin reads a member's private chat, that is recorded too: an `agent_session.admin_override` event with `"action": "read"`, at most once an hour per admin and chat.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/org/audit-logs` | List audit events (`?page=`, `?per_page=`). Owners and admins only |
| `GET` | `/v1/org/audit-logs/export` | Export (`?format=`). Owners and admins only |
