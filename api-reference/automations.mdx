## Inbound triggers

External events → agent runs. See the [Triggers guide](/automations/triggers) for providers, payload matching, routing, and response semantics.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/triggers/hook/{slug}` | **Public ingest endpoint** — no bearer auth; secured by the trigger secret (`X-Webhook-Secret` or HMAC `X-Webhook-Signature`; MS Teams uses the Graph `clientState`). Generic webhooks and MS Teams Graph notifications both land here |
| `POST` | `/v1/triggers` | Create a trigger. Body carries `provider` (`webhook` default, or `msteams` with an `msteams` config block); a `webhook` trigger returns the secret exactly once |
| `GET` | `/v1/triggers` | List triggers (`?agent_id=`) |
| `GET` | `/v1/triggers/{trigger_id}` | Get a trigger (an `msteams` trigger echoes its config + `msteams_status`) |
| `PATCH` | `/v1/triggers/{trigger_id}` | Update (pause/resume, conditions, routes; MS Teams toggles mutable, `upstream` immutable) |
| `DELETE` | `/v1/triggers/{trigger_id}` | Delete (with its delivery log; drops the Graph subscription first) |
| `GET` | `/v1/triggers/{trigger_id}/deliveries` | Delivery log (`?limit=`, max 500) |

A trigger's `provider` is one of `webhook` (default; any system POSTing JSON, with provider-header recognition for GitHub/GitLab/Linear/Shopify/Sentry and more) or `msteams` (a Microsoft Graph chat-message subscription — API/dashboard only, no CLI).

## Schedules

Cron → agent runs. See the [Schedules guide](/automations/schedules).

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/schedules` | Create a schedule (optional `metadata` map) |
| `GET` | `/v1/schedules` | List schedules (`?agent=` ID or name; `?metadata.<key>=<value>` to filter, ANDed) |
| `GET` | `/v1/schedules/{schedule_id}` | Get a schedule (next/last run) |
| `PATCH` | `/v1/schedules/{schedule_id}` | Update (pause/resume, cron, prompt — the agent binding is immutable) |
| `DELETE` | `/v1/schedules/{schedule_id}` | Delete (with its firing log) |
| `GET` | `/v1/schedules/{schedule_id}/firings` | Firing log (`?limit=`, default 100) |

`metadata` is an opaque string map (max 20 entries, 64-character keys, 256-character values) accepted on create and update. A malformed `metadata.` filter returns `400` rather than silently widening the listing.

## Outbound webhooks

Platform events → your endpoints. See the [Outbound webhooks guide](/automations/outbound-webhooks) for event types, signing, and retry behavior.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/org/webhooks` | Create a webhook (signing secret returned once) |
| `GET` | `/v1/org/webhooks` | List webhooks |
| `GET` | `/v1/org/webhooks/{webhook_id}` | Get a webhook |
| `PUT` | `/v1/org/webhooks/{webhook_id}` | Update |
| `DELETE` | `/v1/org/webhooks/{webhook_id}` | Delete |
| `POST` | `/v1/org/webhooks/{webhook_id}/test` | Send a `webhook.test` event |
| `GET` | `/v1/org/webhooks/{webhook_id}/deliveries` | Delivery history (`?limit=`, default 20, max 200) |
| `GET` | `/v1/org/webhooks/deliveries/{delivery_id}` | Get a delivery |
| `POST` | `/v1/org/webhooks/deliveries/{delivery_id}/retry` | Re-send a delivery (`422` once max attempts are spent) |
