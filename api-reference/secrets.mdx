Secrets are encrypted at rest and never returned by the API — list responses contain names, versions, and status only. [Agent secrets](/agents/secrets) use the app endpoints via the agent's backing app.

## App secrets

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/apps/{app_id}/secrets` | Set (stage) a secret |
| `GET` | `/v1/apps/{app_id}/secrets` | List secrets (names and metadata only) |
| `POST` | `/v1/apps/{app_id}/secrets/deploy` | Deploy staged secrets to running machines |
| `DELETE` | `/v1/apps/{app_id}/secrets/{name}` | Delete a secret |

## Global (org) secrets

Given to every agent in the organization, or to chosen agents only; an agent's own secret of the same name wins. See the [Global Secrets guide](/secrets).

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/org/secrets` | Set an org-wide secret. Optional `agents` (ids or names) gives it to those agents only; `all_agents: true` to every agent |
| `GET` | `/v1/org/secrets` | List org-wide secrets, each with `all_agents` and the `agents` you can see it given to |
| `PATCH` | `/v1/org/secrets/{name}` | `{"all_agents": false, "agents": [...]}` gives it to those agents only (the list is replaced); `{"all_agents": true}` to every agent. Operator role |
| `DELETE` | `/v1/org/secrets/{name}` | Delete an org-wide secret |
