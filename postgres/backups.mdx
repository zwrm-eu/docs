ZWRM supports full backups and point-in-time recovery (PITR) for PostgreSQL databases. Backups are stored externally and can be used to restore a database in place or into a new database instance.

## Enable WAL archiving

Before creating backups, enable WAL (Write-Ahead Log) archiving on the database:

```bash
zwrm postgres backup enable <name>
```

Restart the database after enabling for changes to take effect.

To disable WAL archiving:

```bash
zwrm postgres backup disable <name>
```

## Create a backup

```bash
zwrm postgres backup create <name>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--type` | string | `base` | Backup type: `base` or `logical` |

### Example

```bash
zwrm postgres backup create my-db --type base
```

## List backups

```bash
zwrm postgres backup list <name>
```

Shows all backups for a database with their ID, type, status, size, and creation time.

### Example

```bash
zwrm postgres backup list my-db
```

## Delete a backup

```bash
zwrm postgres backup delete <backup-id>
```

<Warning>Deleting a backup is permanent. You won't be able to restore from it afterward.</Warning>

## Restore a database

By default, restore is an **in-place** operation: it replaces the database's VM with the backup data while keeping the original database ID, credentials, and external domain. Pass `--name` to create a new database from the backup instead, leaving the original untouched.

```bash
zwrm postgres restore <name>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--name` | string | — | Name for the restored database (omit for an in-place restore) |
| `--backup` | string | latest | Specific backup ID to restore from |
| `--pitr` | string | — | Point-in-time recovery target (RFC 3339 timestamp) |
| `--size` | string | same as source | Size preset override: `small`, `medium`, `large` |

<Warning>Without `--name`, restore is **destructive**: the source database's current data is replaced by the backup. The old data volume is kept for 24 hours before cleanup, but treat an in-place restore as overwriting the database. Use `--name` to restore into a new database instead.</Warning>

### Examples

In-place restore from the latest backup (replaces the current data):

```bash
zwrm postgres restore my-db
```

Restore into a new database, leaving `my-db` untouched:

```bash
zwrm postgres restore my-db --name my-db-restored
```

Restore from a specific backup:

```bash
zwrm postgres restore my-db --backup abc12345
```

Point-in-time recovery to a specific moment:

```bash
zwrm postgres restore my-db --pitr "2026-03-10T14:30:00Z"
```

<Tip>PITR requires WAL archiving to be enabled. The target time must fall within the range covered by available WAL segments.</Tip>

## Check restore progress

`zwrm postgres restore` prints the restore ID, mode (in-place or new database), and initial status when it starts. To follow progress from there:

- **`zwrm postgres list`** — during an in-place restore, a temporary `<name>-restore-tmp` database appears while the backup is brought up and disappears once it is swapped in. A `--name` restore shows the new database moving from `creating` to `running`.
- **`GET /v1/postgres/restores/{restore_id}`** — returns the restore's status (`pending`, `restoring`, `completed`, or `failed`), the target database ID, and any error details.
