title: "Linking"
description: "Connect PostgreSQL databases to your applications over private networking."

---

Linking a database to an application enables private network access between them — your app can connect to the database without going over the public internet.

Linking opens the network path only. It sets no secret, `DATABASE_URL` included: you [give the app its connection string](#give-the-app-its-connection-string) yourself.

<Note>
The app must have private networking enabled before it can be linked — set it in the app's `zwrm.toml`:

```toml
[network]
private = true
```

Linking an app without private networking is refused.
</Note>

<Note>
A link hands the app's machines the database's network path, and usually its password, so it follows who may use each side ([private and shared apps](/apps/sharing#linking-databases)): a shared app links only shared databases, and a private app links its owner's private databases and shared ones. Anything else is refused with `409`. While linked, sharing the app or taking the database back is refused too, naming the other side.
</Note>

## Link a database

```bash
zwrm postgres link <database-name>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--app` | string | from `zwrm.toml` | Application to link to |

### Example

```bash
zwrm postgres link my-db --app my-app
```

## Give the app its connection string

Run [`zwrm postgres connect`](/postgres/overview#connect-to-a-database) and store the internal connection string it prints (the one marked *from linked apps*) as the app's `DATABASE_URL` [secret](/apps/secrets):

```bash
zwrm postgres connect my-db
zwrm secrets set DATABASE_URL "postgres://..." --app my-app
```

That connection string carries the database's superuser password. You can also create your own role or database on the cluster and put that in `DATABASE_URL` instead; failover repoints it the same way.

## Failover

When the database fails over to a replica, the control plane checks each linked app's `DATABASE_URL` secret and restarts the app's running machines.

- **It repoints a `DATABASE_URL` that targets this database.** That is a `postgres://` or `postgresql://` URL whose host is one of the database's addresses (the primary's or a replica's), on its direct or pooled port.
- **Only the host changes**, to the new primary's address. The URL keeps its own user, password, database, query, and port, so failover never writes a credential.
- **Any other value is left alone:** another host or port (the external connection string included), the keyword form (`host=... port=...`), or a value that isn't a URL. Update such a value yourself if it should follow the primary.

## Unlink a database

```bash
zwrm postgres unlink <database-name>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--app` | string | from `zwrm.toml` | Application to unlink from |

## View links

```bash
zwrm postgres links
```

| Flag | Type | Description |
|------|------|-------------|
| `--app` | string | Show databases linked to this app |
| `--database` | string | Show apps linked to this database |

These flags are mutually exclusive. If neither is specified, the app name is read from `zwrm.toml`.

### Examples

```bash
# Show databases linked to the current app
zwrm postgres links

# Show databases linked to a specific app
zwrm postgres links --app my-app

# Show apps linked to a specific database
zwrm postgres links --database my-db
```
