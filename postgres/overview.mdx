ZWRM provides managed PostgreSQL databases running in dedicated Firecracker VMs. Each database gets its own isolated environment with persistent storage.

## Create a database

```bash
zwrm postgres create <name>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--size` | string | `small` | Size preset: `small`, `medium`, or `large` |
| `--database` | string | instance name | Initial database name — defaults to the instance name, sanitized to a valid Postgres identifier (e.g. `my-db` → `my_db`) |

After creation, you'll see the host addresses, the credentials, and a connection string. This is the only time `zwrm postgres create` shows the password. To see it again later, use [`zwrm postgres connect`](#connect-to-a-database).

<Tip>Run `zwrm postgres presets` to see what each size includes.</Tip>

### Example

```bash
zwrm postgres create my-db --size medium
```

## Connect to a database

```bash
zwrm postgres connect <name>
```

Shows connection details and ready-to-use `psql` commands, the superuser password included. The database must be running.

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--direct` | bool | `false` | Return the raw Postgres connection (`:5432`), bypassing the pooler |

When a connection pooler (PgBouncer) is enabled for the database, the connection string routes through it by default. Use `--direct` for admin tasks that need session-level features the pooler doesn't support in transaction mode.

### Who can fetch the connection details

- **Members** of the database's organization can.
- **Agents and scoped API tokens** need the `postgres:connect` [capability](/agents/capabilities), plus `postgres:read` for `zwrm postgres connect` to look the database up by name. Agents don't have `postgres:connect` by default, so an agent gets `403` until you grant it.

Every fetch is recorded in the organization's [audit log](/api-reference/platform#audit-logs) as `database.credentials_released`, with who fetched it, which credential they used, and whether it was the direct or the pooled connection string.

### External connections

The external connection string (`<id>.postgres.zwrm.io:5432`, `sslmode=require`) reaches the database from outside ZWRM. It needs TLS: the server name in the TLS handshake picks the database, so a client connecting with `sslmode=disable` is turned away.

An open external connection is not cut by ZWRM platform updates. It does end when:

- the database restarts, is stopped, or fails over to a replica;
- it has sent and received nothing for **1 hour**.

Design long-running clients for both:

- Have your connection pool check connections on checkout, or recycle them before they reach an hour of idle time.
- Reconnect and retry when a connection drops mid-query.
- Session-level state goes with the connection: advisory locks, temporary tables, `SET` parameters and prepared statements. A job that relies on a session-level advisory lock should treat a lost connection as a lost lock.

## List databases

```bash
zwrm postgres list
```

Shows all databases with their ID, name, status, host, size, replica count, backup state, and creation time. The `BACKUP` column reads `off` when WAL archiving is disabled, `ok` when archiving is on and the database is recoverable, and `MISSING` when archiving is on but no recoverable backup exists.

## Stop and start

Stop a database (data is preserved):

```bash
zwrm postgres stop <name>
```

Start it again:

```bash
zwrm postgres start <name>
```

## Destroy a database

```bash
zwrm postgres destroy <name>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--force`, `-f` | bool | `false` | Skip confirmation prompt |

<Warning>Destroying a database permanently deletes all data. This cannot be undone.</Warning>

## Size presets

View available presets and their resources:

```bash
zwrm postgres presets
```

Each preset defines vCPUs, memory, and storage allocation.
