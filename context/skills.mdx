A **skill** is a named instruction bundle that ZWRM materializes into the agent's workspace at `~/.claude/skills/<slug>/`, where the agent auto-discovers it. Skills let you package "how we do X here" once and reuse it across agents.

## Your skills and shared skills

Every member can create skills. A skill you create is **yours and private**: other members don't see it, and it loads only in your own private chats, on the agents where you switch it on for yourself.

**Share** a skill and it joins the organization's library: every member can switch it on for themselves, and operators can switch it on for an agent, so every chat with that agent loads it. Sharing doesn't load it anywhere by itself. Agents can look shared skills up with `find_shared_skills` and `read_shared_skill`; each result says who shared it and that it was written for someone else's work. Sharing keeps you as the owner, and you can take it back at any time. An org admin can take it back too.

| | Who sees it | Who changes it |
|---|---|---|
| Your private skill | You (org admins can see it and delete it) | You |
| A shared skill | Every member | Its owner, and operators and above |
| A built-in | Everyone | Nobody: it comes with platform releases |

## The skill library

```bash
zwrm skills list
zwrm skills create translate --name "Translate" --description "Use when translating documents"
zwrm skills upload translate ./translate-bundle.zip
zwrm skills share translate
zwrm skills unshare translate
zwrm skills delete translate
```

- `create` registers the skill as your own, private one (`--share` shares it right away); `--description` is the when-to-use hint shown to agents and humans.
- `share` and `unshare` put it in the organization's library or take it back.
- `upload` publishes a **bundle** (zip) as the skill's next version and live-pushes it to running workspaces of agents that have the skill enabled. Agents always track the latest version — there is no per-agent pinning.
- `delete` removes the skill from agents and live workspaces.

### Bundle rules

A bundle is a zip with exactly one `SKILL.md` at its root, plus supporting text files (`.md .txt .py .js .ts .mjs .sh .json .yaml .yml .toml .csv .xml .xsd`). Limits: 10 MB compressed, 5 MB uncompressed total, 512 KB per file, 100 files.

Zipping the skill folder itself works — a single wrapper directory is unwrapped automatically, so both `zip -r bundle.zip my-skill/` and compressing the folder in Finder or Explorer are fine. OS junk (`__MACOSX/`, `.DS_Store`, AppleDouble `._*`) is ignored rather than rejected.

### Limits

Up to **100 shared skills per organization**, **100 private skills per member**, and **100 skills switched on per agent**, for the agent and for each member.

## Enabling skills per agent

```bash
zwrm agent skills list my-project
zwrm agent skills enable my-project translate --mine   # for your own private chats with it
zwrm agent skills enable my-project translate          # for the agent: every chat with it
zwrm agent skills disable my-project translate
```

A skill switched on **for the agent** loads in every chat and run with it. That needs the operator role, and the skill must be shared or built in, since everyone using the agent gets it. A skill switched on **with `--mine`** loads only in your own private chats with the agent and runs in your own workspaces, and in a chat you share if you bring your skills along ([`owner_skills`](/api-reference/runs-sessions#sharing-a-chat), or `zwrm agent chat share --skills`); anyone in that chat can then ask the agent what they say. Your own switch wins over the agent's on the same slug, and the agent's wins over a built-in.

Enable/disable live-syncs running workspaces; suspended or cold workspaces pick up changes at the next session start.

## Built-in skills

Every agent gets Anthropic's built-in skills enabled by default:

| Skill | Handles |
|-------|---------|
| `xlsx` | Excel spreadsheets — formulas, formatting, charts, multi-sheet data |
| `docx` | Word documents — styles, tables, images, PDF conversion |
| `pptx` | PowerPoint presentations — layouts, text, images, charts |
| `pdf` | PDFs — merge/split, text and image extraction, form filling |
| `skill-creator` | Authoring new skills and improving existing ones |

They show up in the library with a *built-in* label and are **read-only** — updates come with platform releases. Their content never passes through the platform: at session start, the workspace VM fetches a pinned commit from `github.com/anthropics/skills` into `~/.claude/skills/` (cached on the volume until the pin changes; needs egress to github.com — if the fetch fails, the session starts without them).

The four document skills (`xlsx`, `docx`, `pptx`, `pdf`) are licensed for installation into **Claude Code only**, so they apply only to agents on a Claude Code harness. For any other agent type they are excluded from the effective set — sync removes them from such workspaces — and enabling one via the API returns `400`. Only `skill-creator` (Apache-2.0) is available on every harness.

- Disable per agent with `zwrm agent skills disable <agent> xlsx` or from the agent page.
- An org skill with the same slug takes precedence over a built-in.

## Agent-managed skills

Agents can write skills too. Inside a session an agent has `save_skill`, `update_skill`, and `delete_skill` tools: a skill it authored in its workspace is persisted, validated like any bundle upload, versioned, and synced into its running workspaces.

- **In your private chat**, `save_skill` makes **your own private skill**, switched on for you on that agent. From there the agent can change only your own private skills, never shared ones.
- **In a shared chat or another run**, it adds a skill to the organization's library under the agent's identity, switched on for the agent. That needs the operator role; the agent counts with its creator's role.

An agent never shares a skill or switches one on for the agent from a private chat: people do that.

Ask an agent to "turn this workflow into a skill and save it" and it can, with the built-in `skill-creator` guiding the authoring, test prompts, and iteration.

<Note>
The session tools need the agent's `skills:write` [capability](/agents/capabilities), and they only change skills the calling agent created (in a shared chat) or the member's own (in a private chat); built-ins are read-only to everyone. Over the REST API an agent credential counts with its creator's role in shared chats and runs, so an agent whose creator is an operator can change shared skills there. If agents shouldn't have that authority, narrow `skills:write` out of their [allowed scopes](/agents/capabilities); that turns the session tools off too.
</Note>

## Hand-dropped skills

You can also drop any skill directly into `~/.claude/skills/<name>/` on the workspace. Hand-dropped directories are never touched by the platform sync — even if a library skill later uses the same slug.
