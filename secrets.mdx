Global secrets are encrypted environment variables stored at the **organization level**. Every agent in your organization gets them when it starts, unless you give a secret to chosen agents only. There's no need to set the same secret on each agent. Apps don't get them; give an app its own [app secrets](/apps/secrets).

## How they work

An agent's VM starts with the global secrets it gets, then its own [agent secrets](/agents/secrets). If both have a secret of the same name, the agent's own wins. This lets you set sensible defaults globally and override them where needed.

### Which agents get a secret

A new global secret reaches every agent. An operator can give it to chosen agents only, and back to every agent:

```bash
zwrm org secrets agents STRIPE_KEY billing-bot finance   # only these agents
zwrm org secrets agents STRIPE_KEY --all                # every agent again
zwrm org secrets set STRIPE_KEY --stdin --agents billing-bot   # when setting it
```

<Note>
Anyone who can chat with an agent can usually get it to reveal the secrets in its environment. A secret that reaches every agent also reaches every member's [private agents](/agents/overview#private-and-shared-agents). Give a sensitive secret to the agents that need it, and keep `secrets:write` out of the [capabilities](/agents/capabilities) of every other agent: an agent with it can change which agents get a secret, its own included.
</Note>

Operators choose among the agents they can use: shared agents and their own. A secret given to a member's private agent stays with it whoever changes the list, admins included: only its owner takes it off.

## Common use cases

- **API keys** shared across multiple services (e.g. `DATADOG_API_KEY`, `SENTRY_DSN`)
- **Registry credentials** for private Docker images
- **Shared database URLs** used by several apps
- **Organization-wide config** like `LOG_LEVEL` or `ENVIRONMENT`

## Managing global secrets

Manage global secrets with the `zwrm org secrets` CLI, the [ZWRM Dashboard](https://dashboard.zwrm.eu), or the REST API.

### CLI

#### Set a global secret

```bash
zwrm org secrets set DATADOG_API_KEY "your-key-here"
```

Also accepts the `NAME=value` form. Prefer `--stdin` to keep the value out of your shell history and the process table:

```bash
printf '%s' "$DATADOG_API_KEY" | zwrm org secrets set DATADOG_API_KEY --stdin
```

Updating an existing secret increments its version.

#### List global secrets

```bash
zwrm org secrets list
```

Shows names, versions, and update timestamps. Values are never exposed.

#### Remove a global secret

```bash
zwrm org secrets unset DATADOG_API_KEY
```

#### Import from an env file

```bash
zwrm org secrets add --from-file .env
```

Creates a global secret for each `KEY=value` pair in the file; lines starting with `#` are ignored.

### REST API

All endpoints require authentication and operate on the authenticated user's organization.

#### Set a global secret

```bash
curl -X POST https://zwrm.io/v1/org/secrets \
  -H "Authorization: Bearer $ZWRM_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "DATADOG_API_KEY", "value": "your-key-here"}'
```

Returns `201` for new secrets, `200` for updates. Updating a secret increments its version. Add `"agents": ["billing-bot"]` to give it to those agents only, or `"all_agents": true` to give it to every agent again.

#### Choose which agents get a global secret

```bash
curl -X PATCH https://zwrm.io/v1/org/secrets/STRIPE_KEY \
  -H "Authorization: Bearer $ZWRM_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"all_agents": false, "agents": ["billing-bot", "finance"]}'
```

`all_agents` is required. `agents` takes agent ids or names, replaces the list, and is only allowed with `all_agents` false; other members' private agents on the list stay on it. Needs the operator role. Returns the secret's metadata, with `hidden_agents` counting the agents on the list you can't see.

#### List global secrets

```bash
curl https://zwrm.io/v1/org/secrets \
  -H "Authorization: Bearer $ZWRM_API_TOKEN"
```

Returns secret names, versions, and timestamps, with `all_agents` and the ids of the `agents` it is given to, the ones you can see. Values are never exposed.

#### Delete a global secret

```bash
curl -X DELETE https://zwrm.io/v1/org/secrets/DATADOG_API_KEY \
  -H "Authorization: Bearer $ZWRM_API_TOKEN"
```

## Secret naming rules

Global secrets follow the same naming rules as app secrets: names must start with a letter or underscore and contain only letters, numbers, and underscores (e.g. `MY_SECRET_123`).
