Agent secrets are encrypted environment variables scoped to a specific agent. They work the same way as [app secrets](/apps/secrets) but are resolved by agent instance name, and are injected into every VM that boots for that agent — runs, chats, and SSH sessions alike.

## Required credentials

The CLI never prompts for credentials — set them yourself with `zwrm agent secrets set`, or from the dashboard's ready-checklist. What each runtime requires:

| Secret | Agents | Notes |
|--------|--------|-------|
| `ANTHROPIC_API_KEY` **or** `CLAUDE_CODE_OAUTH_TOKEN` | claude | Either satisfies the requirement |
| `OPENAI_API_KEY` **or** `OPENAI_CODEX_AUTH` | codex | API key, or a ChatGPT-subscription login (the whole `~/.codex/auth.json`); if both are set the subscription wins. See [Models](/agents/models#codex) |
| *(none)* | pi (zwrm runtime) | No model credential — the platform provides it; usage is billed to [credits](/billing/credits) |
| *(none)* | opencode (beta) | Same as the zwrm runtime: no model credential, billed to [credits](/billing/credits) — except models from your own [external providers](/agents/external-providers), which use the credential stored on the provider |

Two **optional** extras are worth setting on most agents — not required, and not on the checklist: `GITHUB_TOKEN` (used by `gh` and git push/pull; when set, `gh` authenticates from it automatically at VM boot) and `GIT_AUTHOR_NAME` / `GIT_AUTHOR_EMAIL` (git identity).

The dashboard's agent page shows a ready-checklist of required secrets, with alternatives (e.g. subscription vs API key) counted as satisfied by either; a credential set as an [org secret](/secrets) satisfies the check the same as an agent secret. The gateway token behind the zwrm runtime and OpenCode (`ZWRM_GATEWAY_TOKEN`) is **reserved** — the platform owns it, and setting it as an agent or org secret is rejected.

<Note>
Credentials for [connectors](/context/connectors) are **not** agent secrets — they live at the MCP gateway and never enter the VM.
</Note>

## Set a secret

```bash
zwrm agent secrets set <NAME> --stdin
zwrm agent secrets set <NAME>=<VALUE>
zwrm agent secrets set <NAME> <VALUE>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--instance` | string | `default` | Agent instance name |
| `--stdin` | bool | `false` | Read the value from standard input — recommended, since the value never appears in argv or your shell history |

### Examples

```bash
printf '%s' "$GITHUB_TOKEN" | zwrm agent secrets set GITHUB_TOKEN --stdin --instance my-project
zwrm agent secrets set DATABASE_URL=postgres://user:pass@host/db
zwrm agent secrets set API_KEY "sk-1234567890"
```

## List secrets

```bash
zwrm agent secrets list
```

Shows secret names, versions, status (staged or deployed), and last updated time. Secret values are never displayed.

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--instance` | string | `default` | Agent instance name |

**Alias:** `zwrm agent secrets ls`

## Remove a secret

```bash
zwrm agent secrets unset <NAME>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--instance` | string | `default` | Agent instance name |

## Import from a file

Bulk import secrets from a `.env` file:

```bash
zwrm agent secrets add --from-file <path>
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--from-file` | string | — | Path to `.env` file (required) |
| `--instance` | string | `default` | Agent instance name |

The file should contain `KEY=value` pairs, one per line. Lines starting with `#` are treated as comments and ignored. Quoted values (single or double) are supported.
