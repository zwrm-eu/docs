A preset is a ready-made agent: a job description with instructions, the tools it needs from your connected integrations (with the ones that send things outside asking first), routines it runs on a schedule, a runtime and daily limits, in English and German.

```bash
zwrm agent presets                       # list them; tools marked * aren't connected yet
zwrm agent presets --locale de
zwrm agent create --preset finance       # Hedi, with her default routines
zwrm agent create books --preset finance --locale de \
  --routines open-invoices,incoming-invoices --timezone Europe/Vienna
```

| Preset | Name | Job | Tools |
|--------|------|-----|-------|
| `sales` | Toni | Sales agent | HubSpot, Microsoft 365 |
| `ops` | Wanda | Operations agent | Notion, Microsoft 365, DATEV, GitHub |
| `finance` | Hedi | Finance agent | DATEV, Microsoft 365 |
| `service` | Carla | Customer service agent | Microsoft 365, Front, Notion, GitHub |
| `research` | Ole | Research agent | Notion, HubSpot, Microsoft 365 |
| `reports` | Elsa | Reports agent | HubSpot, DATEV, Microsoft 365 |
| `calendar` | Hugo | Calendar agent | Microsoft 365 |
| `writing` | Pia | Writing agent | Notion, GitHub, Microsoft 365 |

## What creating one does

One request makes the agent, its tools and its routines. If any part fails, nothing is kept.

- **The agent** gets the preset's instructions, runtime, effort and daily limits, its name (`Hedi`) and bird. The handle defaults to the preset's id; pass one to choose your own, and `--name` to rename it.
- **Tools.** For each integration your organization has connected, the agent gets the preset's tools from it. The ones that send things outside, such as sending mail, [ask first](/context/connectors#escalations). Afterwards they are ordinary [agent tools](/context/connectors#choose-an-agents-tools): read and change them with `zwrm agent tools`.
  - A catalog integration counts as connected by its server's address, so a connection you renamed, or a second one, works. A custom server that merely has the same name does not.
  - Integrations you haven't connected, or whose tool list hasn't synced yet, are skipped and listed in the response.
- **Who can use it.** In the dashboard you choose: everyone in the organization (the default) or only you. Through the API it is private unless you pass `visibility: org`. A shared agent's routines are shared too, and if one of its tools acts as one account for everyone, you're asked to confirm first.
- **Routines.** The default routines (`--routines` to pick others, `--routines ""` for none) become [schedules](/automations/schedules). Their times are wall-clock times in Europe/Berlin, or `--timezone`, and stay at that local time across daylight saving. Routines that start on an event, like a new order, need a [trigger](/automations/triggers) and are never created automatically.

Any member can create from a preset. A connection that signs in with one account for everyone is an operator's to give an agent, unless it's your own: for a member, such integrations are marked in the list and left out of the agent (`needs_operator`). In the API: `GET /v1/agent-presets?locale=en|de` and `POST /v1/agent-presets/{preset}/agents` (see the [API reference](/api-reference/agents#presets)).
