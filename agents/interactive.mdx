## SSH

```bash
zwrm agent create my-project --runtime claude  # one-time: store the agent definition
zwrm agent connect my-project                  # boot the workspace VM, open the agent tool
zwrm agent ssh my-project                      # raw shell in the same workspace VM
```

`connect` resolves the agent by exact ID or unambiguous name, boots (or reuses) a VM on its default workspace, and drops you into the agent tool over SSH; `ssh` opens a plain shell in the same VM instead. Disconnecting destroys the VM and keeps the volume. Connecting to a name that doesn't exist offers to create the agent (asking for the runtime) in an interactive terminal; non-interactive use never creates implicitly.

`create` flags:

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--runtime` | string | — | **Required.** Agent runtime: `zwrm`, `claude`, or `codex` |
| `--size` | string | `performance-2x` | VM size preset |
| `--template` | string | — | Agent template: registry ID or `github.com/user/repo` |

`connect` and `ssh` take only the agent name or ID — the stored runtime, size, and template carry over. If the same name exists in more than one of your orgs, use an agent ID or the global `--org` flag.

Runs and chat can share a live SSH VM — an execution's teardown never kills a VM you are SSH-ed into.

## Chat

The dashboard's chat opens a session on the agent's `default` workspace — it boots its own VM and resumes the workspace conversation. Ending the chat releases the VM; the conversation stays resumable.

Over the API, `POST /v1/agents/{agent_id}/sessions` accepts a `session_key` that selects the workspace, exactly like a run's `--session` key: distinct keys give you parallel sessions in separate workspaces, and the same key continues that workspace's conversation. No key means the `default` workspace. See [Runs & sessions](/api-reference/runs-sessions#start-a-session) for the full request body.

## Managing agents

### List

```bash
zwrm agent list
```

Shows all agent instances across your organizations, with type, status, org, size, template, volume, and age.

### Destroy vs delete

```bash
zwrm agent destroy my-project   # stop the VM, keep the volume
zwrm agent delete my-project    # delete the agent entirely: VM, volume, and record
```

`delete` (alias `rm`) accepts `-f/--force` to skip confirmation.

### Resize the volume

```bash
zwrm agent resize my-project --volume 20GB
```

Grow-only; the agent must be stopped.

### Activity log

```bash
zwrm agent logs my-project [--limit 50]
```

Shows connect, disconnect, and reset events.

### Update configuration

```bash
zwrm agent update my-project --model opus --effort high
```

See [Configuring an agent](/agents/overview#configuring-an-agent) for all flags.
