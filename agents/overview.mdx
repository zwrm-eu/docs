ZWRM Agents are AI workers — Claude Code, OpenAI Codex, the native **zwrm runtime**, or OpenCode (beta) — that run in isolated Firecracker microVMs. An **agent is pure configuration** — instructions, default model, effort, VM size, connectors, skills, and budgets. Execution state lives in **workspaces**: a persistent volume plus a session-continuity key. VMs are **ephemeral**: one boots when a run or chat starts and is torn down when it finishes; the workspace volume (files, repos, conversation transcript) is what carries everything forward.

Agents have full access to the ZWRM platform — the `zwrm` CLI is pre-installed and authenticated inside every VM. Your agent can build, deploy, scale, and manage applications directly.

## Quick start

```bash
# Create the agent — the runtime is stored on it (--runtime is required)
zwrm agent create my-project --runtime claude

# Boot into an interactive workspace session
zwrm agent connect my-project

# Dispatch an autonomous run (returns immediately)
zwrm agent run --agent my-project --prompt "Summarize the open PRs in acme/api"
zwrm agent run status <run-id>

# Continue that exact conversation later
zwrm agent run continue <run-id> --prompt "Now address the review feedback"
```

The CLI never prompts for credentials. A claude or codex agent needs its harness credential set as an [agent secret](/agents/secrets) (`zwrm agent secrets set`, or the dashboard's ready-checklist) before its first session; the zwrm runtime needs none. Secrets are injected into every VM at boot, and `gh` authenticates automatically when a `GITHUB_TOKEN` secret is set.

## The model

| Concept | What it is |
|---------|------------|
| **Agent** | A named definition: instructions, defaults (model, effort, size), connectors, skills, budgets. Never owns a VM. |
| **Workspace** | A volume + a session key. Same key ⇒ same conversation and files; no key ⇒ a fresh anonymous workspace (72h TTL). |
| **Run** | One autonomous task: a prompt executed as a headless session in a fresh VM on the chosen workspace. |
| **Session** | One live conversation (a run's headless session, or a dashboard chat). One live session per workspace. |

There is no built-in repo concept: a repo is whatever the prompt (or a skill) clones onto the workspace volume. `gh` is pre-authenticated, so "clone acme/api and open a PR" just works — and the clone persists on the volume for the next run with the same session key.

## Agent types

The runtime is set once, at creation (`zwrm agent create <name> --runtime <zwrm|claude|codex|opencode>`), and picks the harness the agent runs on:

| Type | Harness | Billing |
|------|---------|---------|
| `claude` | Claude Code | Your org's Anthropic credentials |
| `codex` | OpenAI Codex | Your org's OpenAI credentials (API key or ChatGPT subscription) |
| `pi` | The **zwrm runtime** (spelled `zwrm` on the CLI and in the dashboard; EU-hosted open models) | Prepaid [credits](/billing/credits) |
| `opencode` | **OpenCode** — *beta*, enabled per organization by the platform team (same EU-first catalog as the zwrm runtime) | Prepaid [credits](/billing/credits) |

Each harness exposes its own model catalog and reasoning-effort ladder — see [Models](/agents/models). claude and codex run on credentials you bring; the zwrm runtime and OpenCode are metered against prepaid credits with no key to manage for catalog models (their [external-provider](/agents/external-providers) models run on your credential and are billed by your vendor).

Agent names are **unique per organization, across runtimes**: `default` can name a claude agent *or* a codex agent in an org, not both. `zwrm agent connect` resolves the stored agent by name or ID — you never repeat the runtime. Connecting to a name that doesn't exist offers to create it (asking for the runtime) in an interactive terminal; non-interactive use never creates implicitly.

## Configuring an agent

Everything an agent *is* can be changed with a single command — only the flags you pass change:

```bash
zwrm agent update my-project --model opus --effort high --size performance-2x
```

| Flag | Description |
|------|-------------|
| `--size` | Default VM size preset (e.g. `performance-2x`) |
| `--model` | Default model — harness-specific (`opus`/`sonnet`/`fable` for claude, catalog aliases for codex, the zwrm runtime and OpenCode). See [Models](/agents/models) |
| `--effort` | Default reasoning effort: `low`, `medium`, `high`, `xhigh`, `max` |
| `--instructions` | Per-agent system-prompt append |
| `--workspace-ttl` | Keyed workspace retention (e.g. `720h`; `0` = never expire) |
| `--daily-budget` | Daily spend cap in USD (`0` = unlimited) |
| `--max-runs-per-day` | Daily run-count cap (`0` = unlimited) |
| `--allowed-scopes` | [Capabilities](/agents/capabilities) the agent's platform token carries |

## What agents can do

From inside any agent VM, the agent (or you, over SSH) can:

- **Deploy apps** — `zwrm deploy` to build and ship directly from the agent
- **Manage secrets** — `zwrm secrets set` to configure environment variables
- **Create databases** — `zwrm postgres create` to spin up Postgres instances
- **Scale services** — `zwrm scale` to adjust replicas
- **View logs** — `zwrm logs -f` to stream application output
- **SSH into apps** — `zwrm ssh` to debug running VMs
