An agent's **type** — set once at creation — selects the *harness* it runs on, and each harness has its own model catalog, reasoning-effort support, and billing. You pick a model per agent (`--model` on `zwrm agent update`) or per run (`--model` on `zwrm agent run`); values accept the short alias or the full ID, case-insensitive, and an empty value inherits the agent's default (and then the harness default).

## Harnesses at a glance

| Type | Harness | Runs on | Billed as |
|------|---------|---------|-----------|
| `claude` | Claude Code | Your org's Anthropic credentials | Your Anthropic account (metered in USD for [budgets](/agents/budgets)) |
| `codex` | OpenAI Codex | Your org's OpenAI credentials | Your OpenAI account — **not** metered by ZWRM |
| `pi` | The **zwrm runtime** | EU-hosted open models, platform-provided key | Prepaid [credits](/billing/credits) (EUR) |

The `pi` harness is presented as **zwrm** in the dashboard and called the *zwrm runtime* in copy; the stored type, the CLI, and the API all keep the engine name `pi`.

## Claude

Bring your org's Anthropic credentials as an [agent secret](/agents/secrets) — `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`.

| Alias | Model |
|-------|-------|
| `opus` | Claude Opus |
| `sonnet` | Claude Sonnet |

Claude supports all four permission modes and the full effort ladder. Leaving the model empty lets Claude Code pick its own default. The Anthropic-licensed document built-ins (docx/pdf/pptx/xlsx skills) are available **only** on claude agents.

## Codex

Bring your org's OpenAI credentials as an agent secret, either way:

- **`OPENAI_API_KEY`** — bills your OpenAI API account.
- **`OPENAI_CODEX_AUTH`** — a ChatGPT subscription login. It holds the whole `~/.codex/auth.json` record from `codex login` (Codex renews it in place), so store the entire file:

  ```bash
  codex login
  zwrm agent secrets set --agent my-codex OPENAI_CODEX_AUTH "$(jq -c . ~/.codex/auth.json)"
  ```

If both are set, the **subscription wins** so a leftover API key can't quietly start charging.

| Alias | Model | Effort |
|-------|-------|--------|
| `sol` (default) | GPT-5.6 Sol | low → max |
| `terra` | GPT-5.6 Terra | low → max |
| `luna` | GPT-5.6 Luna | low → max |
| `gpt-5.5` | GPT-5.5 | low → xhigh |
| `gpt-5.2` | GPT-5.2 | low → xhigh |

Codex runs on your own OpenAI account, so ZWRM does not meter its cost: the per-agent **daily spend** budget never bites on codex — only the **run-count** cap does. Codex agents express two permission modes (Ask and Bypass). On `gpt-5.5`/`gpt-5.2`, an effort of `max` is clamped down to `xhigh`. Attaching or detaching a connector forces a fresh Codex thread on the next session (Codex freezes its tool set at thread creation).

## The zwrm runtime (`pi`)

The native runtime needs **no credentials from you** — the platform owns the model-provider key and injects it at boot; usage is metered against prepaid [credits](/billing/credits). Every model is **EU-hosted** (the platform guarantee), across multiple EU providers; a model's provider follows from the model, not from any configuration you set.

| Alias | Model |
|-------|-------|
| `glm-5.2` (default) | GLM-5.2 |
| `deepseek-v4` | DeepSeek V4 Pro |
| `kimi-code` | Kimi K2.7 Code |
| `qwen-235b` | Qwen3 235B Instruct |
| `gpt-oss` | gpt-oss 120B |
| `qwen-thinking` | Qwen3 Next 80B Thinking |
| `hermes-405b` | Hermes 4 405B |

Live per-token pricing is shown in EUR in the dashboard (**Settings → Credits → Model pricing**) and via [`GET /v1/credits/pricing`](/billing/credits) — the rate and margin are set per deployment, so the docs don't hardcode numbers. The zwrm runtime expresses two permission modes (Ask and Bypass).

<Note>
The provider API keys (`NEBIUS_API_KEY`, `LYCEUM_API_KEY`) are **reserved for the platform** — they're the billing boundary, so you can't set them as org or agent secrets. That's what makes the zwrm runtime a no-key, credits-metered harness.
</Note>

## If a model leaves the catalog

Catalogs evolve. A stored default model that's no longer offered is re-resolved against the current catalog; if it's gone entirely, the run or session falls back to the harness default and logs a warning rather than failing to boot. Historical `model` values recorded on past runs and sessions are left as-is.
