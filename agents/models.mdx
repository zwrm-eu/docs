An agent's **type** — set once at creation — selects the *harness* it runs on, and each harness has its own model catalog, reasoning-effort support, and billing. You pick a model per agent (`--model` on `zwrm agent update`) or per run (`--model` on `zwrm agent run`); values accept the short alias or the full ID, case-insensitive, and an empty value inherits the agent's default (and then the harness default).

## Harnesses at a glance

| Type | Harness | Runs on | Billed as |
|------|---------|---------|-----------|
| `claude` | Claude Code | Your org's Anthropic credentials | Your Anthropic account (metered in USD for [budgets](/agents/budgets)) |
| `codex` | OpenAI Codex | Your org's OpenAI credentials | Your OpenAI account — **not** metered by ZWRM |
| `pi` | The **zwrm runtime** | EU-first gateway catalog, platform-provided key | Prepaid [credits](/billing/credits) (EUR) |
| `opencode` | **OpenCode** — *beta* | The same EU-first gateway catalog as the zwrm runtime, platform-provided key | Prepaid [credits](/billing/credits) (EUR) |

The `pi` harness is presented as **zwrm** in the dashboard and called the *zwrm runtime* in copy; the CLI spells it `zwrm` too (`--runtime zwrm` — `--runtime pi` is rejected). Only the stored type and the API keep the engine name `pi`.

## Claude

Bring your org's Anthropic credentials as an [agent secret](/agents/secrets) — `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`.

| Alias | Model |
|-------|-------|
| `opus` | Claude Opus 5 |
| `sonnet` | Claude Sonnet 5 |
| `fable` | Claude Fable 5.1 |

Each alias tracks the newest release of its family. To pin a specific release, pass the full model ID instead — `claude-opus-5`, `claude-sonnet-5`, `claude-fable-5`, `claude-fable-5-1`. Both Fable releases are selectable: `fable` resolves to Fable 5.1, while `claude-fable-5` keeps an agent on Fable 5.

Claude supports all four permission modes and the full effort ladder. Leaving the model empty lets Claude Code pick its own default. The Anthropic-licensed document built-ins (docx/pdf/pptx/xlsx skills) are available **only** on claude agents.

<Note>
Fable models run on your Anthropic credentials like the rest of the Claude catalog, but Anthropic gates them: your account needs access to the Fable tier, and they are not served to zero-data-retention organizations. If a run fails at model selection, check your Anthropic account's model access first.
</Note>

## Codex

Bring your org's OpenAI credentials as an agent secret, either way:

- **`OPENAI_API_KEY`** — bills your OpenAI API account.
- **`OPENAI_CODEX_AUTH`** — a ChatGPT subscription login. It holds the whole `~/.codex/auth.json` record from `codex login` (Codex renews it in place), so store the entire file:

  ```bash
  codex login
  jq -c . ~/.codex/auth.json | zwrm agent secrets set OPENAI_CODEX_AUTH --stdin --instance my-codex
  ```

If both are set, the **subscription wins** so a leftover API key can't quietly start charging.

| Alias | Model | Effort |
|-------|-------|--------|
| `sol` (default) | GPT-5.6 Sol | low → max |
| `terra` | GPT-5.6 Terra | low → max |
| `luna` | GPT-5.6 Luna | low → max |
| `gpt-5.5` | GPT-5.5 | low → xhigh |
| `gpt-5.2` | GPT-5.2 | low → xhigh |

Codex runs on your own OpenAI account, so ZWRM does not meter its cost: the per-agent **daily spend** budget never bites on codex — only the **run-count** cap does. Codex agents express two permission modes (Ask and Bypass). On `gpt-5.5`/`gpt-5.2`, an effort of `max` is clamped down to `xhigh`. Attaching or detaching a connector forces a fresh Codex thread on the next session (Codex freezes its tool set at thread creation).

## The zwrm runtime (`pi`)

The native runtime needs **no credentials from you** — the VM boots with a short-lived platform gateway token (`ZWRM_GATEWAY_TOKEN`) and buys its completions from the platform's [LLM gateway](/agents/openai-api); vendor API keys never enter the VM. Usage is metered against prepaid [credits](/billing/credits). The catalog is **EU-first** across several providers — each model's residency is shown as `eu_resident` in the picker and on `GET /v1/openai/models`, and `require_eu_models` enforces EU-only serving for an organization; a model's provider follows from the model, not from any configuration you set.

| Alias | Model |
|-------|-------|
| `auto` (default) | **Smart routing** — the gateway picks a healthy catalog model per request (canonical slug `zwrm/auto`) |
| `glm-5.2` | GLM-5.2 |
| `deepseek-v4` | DeepSeek V4 Pro |
| `kimi-code` | Kimi K2.7 Code |
| `kimi-k3` | Kimi K3 |
| `qwen-235b` | Qwen3 235B Instruct |
| `gpt-oss` | gpt-oss 120B |
| `qwen-thinking` | Qwen3 Next 80B Thinking |
| `hermes-405b` | Hermes 4 405B |
| `glm-5.3-flash` | GLM-5.3 Flash |
| `gpt-5.6-sol` | GPT-5.6 Sol |
| `gpt-5.6-terra` | GPT-5.6 Terra |
| `gpt-5.6-luna` | GPT-5.6 Luna |

Aliases are what the CLI (`--model`) and the dashboard picker take. Inside the VM — the interactive `pi` session and its `/model` UI — models go by their public gateway slug instead (`qwen/qwen3-235b-instruct`), the same names the [OpenAI-compatible API](/agents/openai-api) serves; catalog and price updates land on the next VM boot.

Live per-token pricing is shown in EUR in the dashboard (the **Models** page, and **Settings → Credits → Model pricing**) and via [`GET /v1/credits/pricing`](/billing/credits) — rates and margins are set per deployment (and can differ per provider), so the docs don't hardcode numbers. The zwrm runtime expresses two permission modes (Ask and Bypass).

<Note>
`ZWRM_GATEWAY_TOKEN` is **reserved for the platform** — it's the billing boundary, so you can't set it as an org or agent secret. That's what makes the zwrm runtime a no-key, credits-metered harness. (The provider names `NEBIUS_API_KEY` / `LYCEUM_API_KEY` are no longer reserved — those keys never enter agent VMs anyway.)
</Note>

## OpenCode (`opencode`)

<Warning>
The OpenCode runtime is currently in **beta**, and is **enabled per organization by the platform team** — it is not self-serve. If your organization doesn't see it in the runtime picker, ask us to enable it. Expect rough edges; report anything surprising.
</Warning>

[OpenCode](https://opencode.ai/) is an open-source coding agent. On ZWRM it runs the same way the zwrm runtime does: the VM boots with a platform gateway token, buys its completions from the platform's [LLM gateway](/agents/openai-api), and needs **no credentials from you** for the platform catalog — vendor keys never enter the VM. Catalog usage is metered against prepaid [credits](/billing/credits). The catalog is **EU-first**, not EU-only: each model's residency is shown as `eu_resident` in the picker and on `GET /v1/openai/models`, and an organization can enforce EU-only serving with `require_eu_models`. Models from your own [external providers](/agents/external-providers) are the exception on every count: they run on your credential, are billed by your vendor, and are hosted wherever your endpoint is.

```bash
zwrm agent create my-agent --runtime opencode
zwrm agent run --agent my-agent --model qwen-235b --prompt "Summarize the open issues"
```

- **Models** — the **same catalog and aliases as the zwrm runtime** (the [zwrm runtime catalog](#the-zwrm-runtime-pi) above, `auto` included), plus your organization's [external providers](/agents/external-providers) as `ext/<provider>/<model-id>`. Inside the VM, models go by their gateway slug, as with the zwrm runtime, and catalog updates land on the next VM boot.
- **Permission modes** — Ask and Bypass.
- **Connectors, skills, memory** — connectors ride OpenCode's native MCP client behind the platform permission gate, so escalation and approvals go through the same gate as on the other runtimes (an approval's *edited* input is not applied on OpenCode); [skills](/context/skills) seeded to `~/.claude/skills` are picked up by OpenCode's Claude-compatible skill discovery; [memory](/context/memory) and sleep/park work.
- **Session commands** — OpenCode's own slash commands (built-ins, command files, skill-projected) are listed and invoked through the session commands API, and the operator shell endpoint works unchanged.

An organization's OpenCode access can be withdrawn by the platform team; existing OpenCode agents are then refused at their next session or run (a turn in progress finishes).

## Your own endpoints

Beyond the catalogs above, an organization can register **external OpenAI-compatible endpoints** — a self-hosted vLLM, an Azure OpenAI deployment, a vendor account ZWRM doesn't resell — and use their models on zwrm-runtime and OpenCode agents. They're written `ext/<provider>/<model-id>`, run on your credential, and are billed by your vendor rather than against credits.

```bash
zwrm org llm-provider add myvllm --base-url https://llm.example.com/v1 --api-key -
zwrm agent update my-agent --model ext/myvllm/Qwen/Qwen3-235B-A22B-Instruct-2507
```

See [External model providers](/agents/external-providers) for registration, authentication, and how they differ from catalog models.

## If a model leaves the catalog

Catalogs evolve. A stored default model that's no longer offered is re-resolved against the current catalog; if it's gone entirely, the run or session falls back to the harness default and logs a warning rather than failing to boot. Historical `model` values recorded on past runs and sessions are left as-is.

Models from [external providers](/agents/external-providers) deliberately behave the other way: if the provider is disabled or deleted, runs and sessions pinned to its models **fail with a clear error** instead of degrading, because a silent fallback would move the work onto billed credits.
