All sandbox endpoints are under `/v1/sandboxes`. Requests require authentication and are scoped to the caller's organization.

## Create sandbox

<ParamField body="template" type="string" required>
  Template name or ID to boot from.
</ParamField>

<ParamField body="mode" type="string" default="ephemeral">
  `ephemeral` or `persistent`.
</ParamField>

<ParamField body="size" type="string" default="shared-cpu-1x">
  VM preset. See [VM sizes](/sandbox#vm-sizes).
</ParamField>

<ParamField body="timeout" type="string" default="5m">
  Duration until auto-destroy (ephemeral only). Examples: `5m`, `1h`, `30s`. Max: `24h`.
</ParamField>

<ParamField body="idle_timeout" type="string" default="10m">
  Duration of inactivity before auto-suspend (persistent only).
</ParamField>

<ParamField body="env" type="object">
  Environment variables as key-value pairs.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary metadata as key-value pairs.
</ParamField>

<ParamField body="egress" type="object">
  Outbound firewall policy. Resolution order: the request's `egress` overrides the template's default policy, which overrides the server's configured default (`default_policy` under `[sandboxes.egress]`, set by the operator; `allow_all` when unset). See [Egress controls](/sandboxes/egress).

  - `mode` (string, required) — `allow_all` or `deny_all`
  - `allow_cidrs` (string[]) — CIDRs to allow when mode is `deny_all`
  - `deny_cidrs` (string[]) — CIDRs to explicitly block (evaluated before allows)
  - `allow_ports` (integer[]) — Restrict `allow_cidrs` to these destination TCP ports
</ParamField>

<ParamField body="disk_size_mb" type="integer">
  Writable disk quota in MiB. Overrides the template's default (which itself defaults to 2048). Must be between 256 and 65536 when set.
</ParamField>

<ParamField body="rate_limit" type="object">
  Firecracker drive rate caps. Overrides the template default. All fields optional; zero means unlimited for that dimension.

  - `bandwidth_mbps` (integer) — Steady-state bandwidth cap (MiB/s)
  - `ops_per_sec` (integer) — Steady-state IOPS cap
  - `burst_mbps` (integer) — One-time bandwidth burst allowed at boot (MiB)
  - `burst_ops` (integer) — One-time ops burst allowed at boot
</ParamField>

```bash
POST /v1/sandboxes
```

<CodeGroup>

```bash Request
curl -X POST http://localhost:8080/v1/sandboxes \
  -H "Content-Type: application/json" \
  -d '{
    "template": "python",
    "mode": "ephemeral",
    "timeout": "10m",
    "size": "shared-cpu-2x",
    "env": {"API_KEY": "sk-..."}
  }'
```

```json Response (201)
{
  "id": "sbx_abc123",
  "template_id": "tmpl_xyz",
  "mode": "ephemeral",
  "status": "running",
  "size": "shared-cpu-2x",
  "ip": "172.16.0.2",
  "env": {"API_KEY": "sk-..."},
  "timeout_seconds": 600,
  "expires_at": "2026-04-05T15:10:00Z",
  "egress": {
    "mode": "allow_all"
  },
  "daemon_token": "sbd_...",
  "created_at": "2026-04-05T15:00:00Z",
  "updated_at": "2026-04-05T15:00:00Z"
}
```

</CodeGroup>

The response may also include `metadata`, `volume_id`, `disk_size_mb`, and `rate_limit` when set. `daemon_token` is the in-VM daemon's bearer token, returned on create and on the [get-sandbox](#get-sandbox) detail endpoint (never in list responses) — it lets a client talk directly to the sandbox daemon via the proxy's `/sandboxes/{id}/_api/` path.

| Status | Condition |
|--------|-----------|
| `201` | Sandbox created |
| `400` | Invalid mode, size, timeout, egress policy, disk size, or rate limit |
| `404` | Template not found |

## List sandboxes

Returns all non-destroyed sandboxes for the caller's organization.

<ParamField query="status" type="string">
  Filter by status: `creating`, `running`, `suspended`. Destroyed sandboxes are excluded from all list responses, so `status=destroyed` always returns an empty list.
</ParamField>

```bash
GET /v1/sandboxes
```

<CodeGroup>

```bash Request
curl http://localhost:8080/v1/sandboxes?status=running
```

```json Response (200)
{
  "items": [
    {
      "id": "sbx_abc123",
      "template_id": "tmpl_xyz",
      "mode": "ephemeral",
      "status": "running",
      "size": "shared-cpu-1x",
      "ip": "172.16.0.2",
      "expires_at": "2026-04-05T15:10:00Z",
      "created_at": "2026-04-05T15:00:00Z",
      "updated_at": "2026-04-05T15:00:00Z"
    }
  ],
  "total": 1
}
```

</CodeGroup>

## Get sandbox

```bash
GET /v1/sandboxes/{id}
```

<CodeGroup>

```bash Request
curl http://localhost:8080/v1/sandboxes/sbx_abc123
```

```json Response (200)
{
  "id": "sbx_abc123",
  "template_id": "tmpl_xyz",
  "mode": "persistent",
  "status": "suspended",
  "size": "shared-cpu-1x",
  "idle_timeout_seconds": 600,
  "last_activity_at": "2026-04-05T15:05:00Z",
  "suspended_at": "2026-04-05T15:15:00Z",
  "daemon_token": "sbd_...",
  "created_at": "2026-04-05T15:00:00Z",
  "updated_at": "2026-04-05T15:15:00Z"
}
```

</CodeGroup>

Beyond the fields shared with the create response (`metadata`, `volume_id`, `disk_size_mb`, `rate_limit`, `daemon_token`), the detail endpoint also reports current disk usage for a **running** sandbox — these fields are never populated on list responses:

- `disk_capacity_mb` (integer) — Writable overlay capacity in MiB. Zero means unknown (not sampled: VM on a remote agent, overlay missing, or sampling failed)
- `disk_used_mb` (integer) — MiB currently used
- `disk_used_percent` (number) — Used percentage (capped at 100)

| Status | Condition |
|--------|-----------|
| `200` | OK |
| `403` | Sandbox belongs to different organization |
| `404` | Sandbox not found |

## Destroy sandbox

```bash
DELETE /v1/sandboxes/{id}
```

Returns `204 No Content` on success. Idempotent — safe to call multiple times.

## Keepalive

Extend the expiry of an ephemeral sandbox.

<ParamField body="timeout" type="string">
  New timeout duration from now. Max: `24h`.
</ParamField>

```bash
POST /v1/sandboxes/{id}/keepalive
```

<CodeGroup>

```bash Request
curl -X POST http://localhost:8080/v1/sandboxes/sbx_abc123/keepalive \
  -H "Content-Type: application/json" \
  -d '{"timeout": "30m"}'
```

```json Response (200)
{
  "id": "sbx_abc123",
  "status": "running",
  "expires_at": "2026-04-05T15:30:00Z"
}
```

</CodeGroup>

| Status | Condition |
|--------|-----------|
| `200` | Timeout extended |
| `409` | Not ephemeral, or not running |

## Wake sandbox

Wake a suspended persistent sandbox.

```bash
POST /v1/sandboxes/{id}/wake
```

<CodeGroup>

```bash Request
curl -X POST http://localhost:8080/v1/sandboxes/sbx_def456/wake
```

```json Response (200)
{
  "id": "sbx_def456",
  "status": "running",
  "ip": "172.16.0.6"
}
```

</CodeGroup>

| Status | Condition |
|--------|-----------|
| `200` | Sandbox woken (or was already running) |
| `409` | Sandbox is in a state that cannot be woken |

## Execute command

Run a command inside a running sandbox.

<ParamField body="command" type="string" required>
  The shell command to execute.
</ParamField>

<ParamField body="timeout" type="string" default="30s">
  Execution timeout. Max: `5m`.
</ParamField>

<ParamField body="workdir" type="string">
  Working directory for the command.
</ParamField>

<ParamField body="env" type="object">
  Additional environment variables for this execution.
</ParamField>

```bash
POST /v1/sandboxes/{id}/execute
```

<CodeGroup>

```bash Request
curl -X POST http://localhost:8080/v1/sandboxes/sbx_abc123/execute \
  -H "Content-Type: application/json" \
  -d '{
    "command": "python3 -c \"import os; print(os.cpu_count())\"",
    "timeout": "10s"
  }'
```

```json Response (200)
{
  "exit_code": 0,
  "stdout": "1\n",
  "stderr": "",
  "duration_ms": 87
}
```

</CodeGroup>

| Status | Condition |
|--------|-----------|
| `200` | Command completed (check `exit_code` for success/failure) |
| `400` | Missing command or invalid timeout |
| `409` | Sandbox not running |

## Upload file

Write a file to the sandbox filesystem.

```bash
PUT /v1/sandboxes/{id}/files/{path}
```

Send the file contents as the request body. Parent directories are created automatically.

```bash
curl -X PUT http://localhost:8080/v1/sandboxes/sbx_abc123/files/home/user/main.py \
  --data-binary @./main.py
```

| Status | Condition |
|--------|-----------|
| `204` | File uploaded |
| `400` | Invalid path (root, contains `..`) or exceeds 100 MB |
| `409` | Sandbox not running |

---

## Download file

Read a file from the sandbox filesystem.

```bash
GET /v1/sandboxes/{id}/files/{path}
```

Returns the raw file contents with `Content-Type: application/octet-stream`.

```bash
curl http://localhost:8080/v1/sandboxes/sbx_abc123/files/home/user/output.json -o output.json
```

| Status | Condition |
|--------|-----------|
| `200` | File contents |
| `404` | File not found |
| `409` | Sandbox not running |
