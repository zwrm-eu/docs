By default, sandbox VMs have unrestricted outbound access to the internet. Egress controls restrict it by IP address and by site, per sandbox or as a default for all sandboxes created from a given template. Agents use the same policy shape; see [Network policy](/agents/network-policy).

## Modes

| Mode | Behavior |
|------|----------|
| `allow_all` | All outbound traffic is permitted (default), except `deny_cidrs` and `deny_domains`: a block list |
| `deny_all` | All outbound traffic is dropped unless allowed by `allow_cidrs` or `allow_domains`: an allow list |

The metadata service at `169.254.169.254` is always reachable regardless of the policy. The in-VM agent daemon uses it to fetch its auth token at boot.

## Policy fields

<ParamField body="mode" type="string" required>
  `allow_all` or `deny_all`.
</ParamField>

<ParamField body="allow_cidrs" type="string[]">
  CIDRs to allow outbound traffic to. Only evaluated when `mode` is `deny_all`. Example: `["1.1.1.1/32", "8.8.8.8/32"]`.
</ParamField>

<ParamField body="deny_cidrs" type="string[]">
  CIDRs to deny. Under `allow_all` they form a block list; under `deny_all` they are evaluated before `allow_cidrs`, so use them to carve out subnets from a broad allow rule. Example: `["10.0.0.0/8"]`.
</ParamField>

<ParamField body="allow_domains" type="string[]">
  Sites to allow over HTTP and HTTPS (ports 80 and 443), each including its subdomains. Only with `deny_all`. Example: `["pypi.org", "files.pythonhosted.org"]`.
</ParamField>

<ParamField body="deny_domains" type="string[]">
  Sites to block, each including its subdomains. In either mode. Example: `["example.com"]`.
</ParamField>

<ParamField body="allow_ports" type="integer[]">
  Restrict `allow_cidrs` rules to these destination TCP ports. If omitted, the allowed CIDRs are reachable on any port. Requires `allow_cidrs` to be set. Example: `[443, 8080]`.
</ParamField>

## Validation

The API validates egress policies on create and returns `400` for:

- Unknown mode (must be `allow_all` or `deny_all`)
- `allow_all` combined with `allow_cidrs`, `allow_ports`, or `allow_domains`
- A domain entry that is an IP address (use the CIDR fields) or not a valid domain
- `allow_ports` set without `allow_cidrs`
- Any `allow_cidrs` entry that overlaps the VM subnet (e.g. `172.16.0.0/16`) — this would punch a hole in cross-app isolation. `0.0.0.0/0` overlaps everything, so it is always rejected; for "everything except X", use `allow_all` with `deny_cidrs` or `deny_domains`
- Any `deny_cidrs` entry that covers the metadata service address (`169.254.169.254`) — this would brick the in-VM daemon's token fetch
- Malformed CIDR notation
- Port numbers outside 1–65535

## Per-sandbox egress

Pass an `egress` object when creating a sandbox to override the template default.

<Tabs>
  <Tab title="CLI">
    ```bash
    # Block all outbound except HTTPS to Cloudflare DNS
    zwrm sandbox create --template python \
      --egress-mode deny_all \
      --egress-allow-cidr 1.1.1.1/32 \
      --egress-allow-cidr 1.0.0.1/32 \
      --egress-allow-port 443

    # Allow a provider's range, but carve out one subnet from it
    zwrm sandbox create --template python \
      --egress-mode deny_all \
      --egress-allow-cidr 203.0.113.0/24 \
      --egress-deny-cidr 203.0.113.128/25
    ```

    ```bash
    # Allow only PyPI, by site
    zwrm sandbox create --template python \
      --egress-allow-domain pypi.org \
      --egress-allow-domain files.pythonhosted.org

    # Everything except a few sites and a range
    zwrm sandbox create --template python \
      --egress-deny-domain example.com \
      --egress-deny-cidr 198.51.100.0/24
    ```

    <Warning>
    `--egress-allow-cidr 0.0.0.0/0` is always rejected with `400`, because any allow-CIDR that overlaps the VM subnet would punch a hole in cross-app isolation. For "everything except X", use deny flags alone (`allow_all` mode).
    </Warning>

    Flags (available on `sandbox create` and `sandbox run`):

    | Flag | Description |
    |------|-------------|
    | `--egress-mode` | `allow_all` or `deny_all`. When omitted, any allow flag makes it `deny_all` and deny flags alone make it `allow_all`. |
    | `--egress-allow-cidr` | Allow outbound to this CIDR (repeatable). Implies `deny_all`. |
    | `--egress-deny-cidr` | Deny outbound to this CIDR (repeatable). |
    | `--egress-allow-port` | Restrict `--egress-allow-cidr` to this TCP port (repeatable). |
    | `--egress-allow-domain` | Allow this site and its subdomains over HTTP and HTTPS (repeatable). Implies `deny_all`. |
    | `--egress-deny-domain` | Block this site and its subdomains (repeatable). |
  </Tab>
  <Tab title="API">
    ```bash
    curl -X POST http://localhost:8080/v1/sandboxes \
      -H "Content-Type: application/json" \
      -d '{
        "template": "python",
        "mode": "ephemeral",
        "timeout": "10m",
        "egress": {
          "mode": "deny_all",
          "allow_cidrs": ["1.1.1.1/32", "1.0.0.1/32"],
          "allow_ports": [443]
        }
      }'
    ```

    The resolved policy is echoed back in the sandbox response:

    ```json
    {
      "id": "sbx_abc123",
      "status": "running",
      "egress": {
        "mode": "deny_all",
        "allow_cidrs": ["1.1.1.1/32", "1.0.0.1/32"],
        "allow_ports": [443]
      }
    }
    ```
  </Tab>
</Tabs>

## Template-level egress defaults

Set a default egress policy on a template so every sandbox created from it inherits the same restrictions.

<Tabs>
  <Tab title="CLI">
    ```bash
    zwrm templates create secure-python \
      --dockerfile ./Dockerfile \
      --egress-mode deny_all \
      --egress-allow-cidr 151.101.0.0/16 \
      --egress-allow-cidr 146.75.0.0/16 \
      --egress-allow-port 443
    ```

    Every sandbox created from this template can only reach PyPI's CDN ranges over HTTPS, unless the create request overrides the policy.
  </Tab>
  <Tab title="API">
    ```bash
    curl -X POST http://localhost:8080/v1/templates \
      -H "Content-Type: application/json" \
      -d '{
        "name": "secure-python",
        "dockerfile": "FROM python:3.12-slim",
        "egress": {
          "mode": "deny_all",
          "allow_cidrs": ["151.101.0.0/16", "146.75.0.0/16"],
          "allow_ports": [443]
        }
      }'
    ```
  </Tab>
</Tabs>

<Note>
The subnet-overlap check runs when a sandbox is created, against the cluster's VM subnet. A template policy whose `allow_cidrs` overlap the VM subnet (such as `0.0.0.0/0`) will cause every sandbox create from that template to fail with `400`.
</Note>

When creating a sandbox, you can override the template's default by passing a different `egress` object. Passing no `egress` field inherits the template default.

<Info>
Rebuilding a template (`zwrm templates rebuild`) does not change the stored egress policy. The policy is attached to the template record, not the image.
</Info>

## How it works

Egress rules are implemented as iptables rules in the `ZWRM` chain on the host. When a sandbox is created with a `deny_all` policy, the manager installs:

1. **Deny rules** — one `DROP` per `deny_cidrs` entry, inserted at the top of the chain
2. **Allow rules** — one `ACCEPT` per `allow_cidrs` entry (optionally port-scoped), inserted directly below the deny rules
3. **Catch-all deny** — a final `DROP` for all traffic from the sandbox IP, appended at the bottom of the chain

The always-allow rule for the metadata service (`169.254.169.254/32`) is appended once at startup, so per-sandbox rules are inserted *above* it in the chain. The metadata service nonetheless stays reachable under any policy: the per-sandbox catch-all `DROP` is appended below the metadata `ACCEPT`, and any `deny_cidrs` entry that would cover the metadata address is rejected at validation time.

Site rules (`allow_domains`, `deny_domains`) are enforced by the host's egress gateway. The firewall redirects the sandbox's TCP 80 and 443 to it; the gateway reads the name each connection asks for (the TLS server name, or the HTTP `Host` header), decides, and connects to that name itself rather than to the address the sandbox chose. While site rules are set, UDP 443 (HTTP/3) is dropped so clients fall back to TCP, and under `deny_all` DNS to the VM's resolvers stays allowed. See [what a policy can and can't stop](/agents/network-policy#what-a-policy-can-and-cant-stop).

Rules are cleaned up automatically when the sandbox is destroyed or suspended.
