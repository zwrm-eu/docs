## Log in

```bash
zwrm auth login
```

Opens your browser to complete the authentication flow. Your token is saved to `~/.zwrm/credentials.json`.

For headless environments (SSH sessions, CI pipelines), create a long-lived token with [`zwrm auth tokens create`](#api-tokens) and pass it directly:

```bash
zwrm auth login --token <your-api-token>
```

## Log out

```bash
zwrm auth logout
```

Removes `~/.zwrm/credentials.json`.

## Check your identity

```bash
zwrm auth whoami
```

Shows your user ID, email, and name.

## View your token

```bash
zwrm auth token
```

Displays your current token in masked format and shows where it was loaded from (environment variable or credentials file).

## API tokens

Create long-lived API tokens for CI/CD pipelines and headless environments:

```bash
zwrm auth tokens create --name github-actions --expiry 8760h
```

The token is displayed only once — store it securely (e.g. as a GitHub Actions secret), then use it via `ZWRM_API_TOKEN` or `zwrm auth login --token`.

| Flag | Description |
|------|-------------|
| `--name` | Token name, e.g. `github-actions` (required) |
| `--expiry` | Expiry duration, e.g. `8760h` for 1 year (empty = never expires) |
| `--scopes` | Comma-separated capabilities, e.g. `apps:read,deploy` (empty = unrestricted token) |
| `--org` | Organization ID or slug a scoped token is bound to (default: your target org) |

With `--scopes` the token becomes a capability-scoped credential, confined to one organization and the capabilities you grant.

List your tokens or revoke one by ID:

```bash
zwrm auth tokens list
zwrm auth tokens revoke <token-id>
```

## Integration tokens

In a [shared chat](/api-reference/runs-sessions), every message names the member who sent it, and the agent is told who is talking. With a token, the named member is the token's owner.

An app that sends many people's messages through one token, such as a helpdesk or a chat front end, can't say who is speaking, so every message would name you. Mark such a token as an integration token, and what it sends into a shared chat names nobody:

```bash
# a new token for the app
zwrm auth tokens create --name helpdesk --integration

# or mark one the app already uses
zwrm auth tokens update <token-id> --integration
```

- Members' own messages in the same chat keep their names.
- The agent is told that a message naming nobody came through an app or an automation.
- Only the token's owner can mark it. `--integration=false` clears the mark.
- A scoped token can't be an integration token, because scoped tokens don't send chat messages.

Over the API, set `"integration": true` when creating a token (`POST /v1/auth/tokens`), or send `PATCH /v1/auth/tokens/{token_id}` with `{"integration": true}`.

## Token resolution

ZWRM looks for your API token in this order:

1. `ZWRM_API_TOKEN` environment variable
2. `~/.zwrm/credentials.json` file

Setting `ZWRM_API_TOKEN` to a token minted with [`zwrm auth tokens create`](#api-tokens) is useful for CI/CD pipelines and automation:

```bash
export ZWRM_API_TOKEN="your-token-here"
zwrm deploy
```

## Credentials file

The credentials file is stored at `~/.zwrm/credentials.json` with restricted permissions (mode `0600`):

```json
{
  "token": "...",
  "user": {
    "id": "...",
    "email": "user@example.com",
    "name": "User Name"
  }
}
```
